# 已失败任务原地恢复计划

2026-10-18，用户明确要求：被 Paseo 正式标为失败的原任务也应原地恢复。

**最新边界：用户明确禁止修改 Paseo，要求在插件内取舍。宿主修改路线关闭，不改源码、SDK 安装包或已安装程序。当前只讨论插件内折中，尚未实现或部署。**

## 插件内推荐折中（待用户确认）

将“原地恢复”定义为：在原 Agent 内恢复原 ChatGPT 任务的同步与操作，不强求复活 Paseo 原生运行状态。

- 必保：同一 Agent/ChatGPT 对话与原任务；不重发原消息、不自动授权；恢复结果先保存在 CIP，不能因展示失败而丢弃。
- 展示：用插件自有的“任务恢复”卡片呈现当前进度、完整正文、最新工具状态及停止入口；保持固定卡片身份。使用公开 `agent.timeline.append`，不把恢复输出塞进可能被宿主丢弃的 Provider pending 流。长正文由本机 RPC 读取，不塞入 64 KiB 的卡片 data。此路线需独立验证，不是已完成功能。
- 让步：Paseo 顶部及原生运行/完成信号可能仍显示失败；旧错误和旧原生工具卡不追改。最新任务状态以恢复卡为准，不保证回填成原生 assistant/tool 历史样式。
- 并发：插件收到的新消息排队，不承诺恢复与新消息的原生状态无缝并行；恢复卡与其数据保存不依赖该原生状态。
- 限制：这里只恢复已执行原任务的观察/结果，不自动重跑真实失败的 ChatGPT 任务或远程工具。授权仍需用户决定。

公开接口可行性依据：已安装 beta.2 SDK 提供 `PaseoAgentTimelineHandle.append`；原版 `session.js.handleAgentTimelineAppendRequest` 直接调用 AgentManager.appendTimelineItem 并返回 seq/epoch，不经过 Provider 的 pending 暂存入口。仍需验证更新幂等、跨新提示并发、重启重建、长正文、Stop/授权和移动端渲染。

## 之前的完整验收目标（已要求取舍，不再强制全部满足）

- 原 Paseo Agent、Provider 会话、ChatGPT 对话和原生用户消息保持不变。
- 不重发用户消息，不制造新的用户提示或重复的 prompt_result，不自动批准工具、不重启/重开 Agent 或修改 Paseo 安装包。
- 只在新页面证明确认原用户锚点仍存在、仍是最新用户消息后恢复原任务的观察；用户取消、停止结果不明、未确认送达、归档、新轮次等仍拒绝恢复。不宣称自动重跑真正失败的网页任务或远程工具。
- 正文与卡片身份保持不变，恢复期间可停止，完成后 Agent 回到空闲并能接受新消息。

## 已验证但否决的插件别名方案

新宿主运行标识确实能避开 beta.2 的 finalized-ID guard，在同一会话从 error → running → idle，且不改变原 Broker turnId / lease / nativeMessageId。但它只证明生命周期的局部可行性，不满足完整交付要求。

原版宿主隔离执行已确认两条独立阻塞：

1. 同一 callId 的工具卡片只在宿主 turnId 相同时合并。原运行中的卡片与新恢复标识下的完成更新会成为两张卡片（一张仍 running，一张 completed）。不能靠不展示真正的工具结果来掩盖。
2. 新提示的宿主 pending 窗口早于 Provider 收到消息。恢复 start/正文/完成进入这个窗口后，如果新提示在发送前失败，原版宿主会丢弃这些事件。Provider admission 标志、commands() 或延后一个事件循环都不是覆盖该窗口的原子证明。

历史 System Error 保留不是阻塞；不要求擦掉真实失败历史。原生 Send lease 应保持稳定，过期观察可另用 observation epoch 隔离。

证据在工作区 `../logs/inplace-recovery-20261018/`：protocol-probe（生命周期局部成立）、blocker-probes（重复工具卡片与 pending 丢内容各已复现）、alias-draft-gates/tdd-before（仅供复现，别名草稿不是验收契约）。所有实验均用临时状态/浏览器命令替身及字节匹配的官方 beta.2 宿主类，不连接真实账号。

不完整的 Broker 改动已撤回，Broker 与线上 alpha.4.26 逐字节相同；原 OBS-P1 不改绿、不跳过。alpha.4.27 文案候选仍独立保留，未部署。

## 之前严格目标所需的宿主能力（用户禁止，不能实施）

- **原子恢复准入**：与新提示的 pending/active 准入在同一宿主执行队列中仲裁，按恢复 attemptId 幂等返回 accepted/busy；提交失败可释放保留，不以发送新用户提示取得运行资格。
- **执行与原始内容归属分离**：恢复 attempt 与原失败执行区分，但原消息、工具的逻辑归属必须稳定。宿主可在获准恢复时保留原逻辑 turnId，或显式支持相关恢复 attempt 下的稳定 source-item 身份；不能全局去掉工具 turnId 检查而误合并其他任务。旧执行的完成事件仍拒绝。
- **准入前过滤与可靠交付**：恢复 attempt/观察 epoch 在进入 pending 暂存前验证；可恢复的正文及终态不能随不相关的新提示失败而被丢弃。需要明确确认/重试语义，而非靠插件猜测已显示。
- **公开能力协商**：无此能力的旧宿主继续安全拒绝，不偷偷调用私有接口、改安装包或伪造成功。自动恢复不等于重新执行真正失败的 ChatGPT/远程工具。

以上都是待新增的能力，不是 beta.2 已有的 API。用户已明确禁止修改宿主；本节仅保留根因与历史分析，不构成后续实现计划。

撤回原地恢复草稿后：默认 533 项 532 过、1 个既有 OBS-P1 失败、0 skip；原版 beta.2 宿主 13/13，typecheck 与 diff --check 通过。新增原地恢复验收草稿只保留为日志中的独立实验，不计作已实现或默认通过的测试。

## 之前严格目标的门禁（保留为能力边界，不冒充已通过）

1. 同一已失败前台连接自动恢复；原生身份不变、无额外浏览器命令；正文和工具卡片各一次。
2. 重复恢复幂等；多次失败/恢复不复用已退役的恢复运行标识。
3. Paseo Stop 经原 Provider 会话送到原网页任务，确认后取消恢复运行，无悬挂 run。
4. 连接/进程重建保持已持久化映射；旧订阅证明和旧终态不能解锁或结束新运行。
5. 与配置、新提示（含宿主 pending 窗口、发送前失败）、停止、归档和新网页轮次竞争时不误发、不丢正文、不抢占新任务。
6. 失败前的工具授权不自动重放；恢复后重新读取当前授权框，仍由用户确认。
7. 覆盖官方 0.11.4、beta.1、beta.2 原版类及实际浏览器链路。离线通过不等于真实账号验收。

本计划不授权部署或改动真实故障会话。先在隔离状态中实现和验证；遇到协议无法满足的竞态须明确报告，不以削弱断言或伪造完成掩盖。
