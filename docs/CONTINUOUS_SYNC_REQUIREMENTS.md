# CIP 持续同步：用户确认的需求

状态：需求已确认，尚未据此修改生产逻辑或部署。下列要求是验收目标，不代表当前版本已全部支持。

## 统一规则

对话绑定期间，持续读取当前对话页面的可见内容，持续按按钮汇报状态，并保真同步到 Paseo。运行中、待命、异常均不关闭内容监听；不按状态拆成不同采集规则，不为授权单独增加监听例外。

按钮判断：可见停止按钮为运行中；可见发送或开始语音按钮且无停止按钮为待命；复查仍无法识别这些按钮为异常／状态无法确认。按钮启用状态另行记录，不用原生 in_progress/complete、正文内容或同步是否完成判断网页状态。

先采集，后归类。内容分为公开思考／工作过程、Allow/Deny 授权请求、输出信息。三类不是采集白名单；输出信息兜底正文、产物、网页错误、提示及暂时不能分类的信息，保留原文和来源。没有输入框的整页错误提示也要读取、传递。

## 正确分型与原生正式回答（用户最新确认）

Work 是过程折叠容器，不是单一助手消息。展开后多出的公开摘要、工具活动及助手进度，与 Work 外的正式回答分别采集、分别标识。折叠/展开不能改写正式回答。正式回答保持 Paseo 原生 assistant_message 身份，不能预先将全部输出改为插件内容，也不能因合成的非前缀改写/跨段工具限制就宣布正常原生工作流不可用。先验证正确分型的完整原生流程；真实触发的接口限制单独报告，不擅自降级。

## 已确认的 Paseo 行为

1. 网页进入待命时通知 Paseo 本轮结束；持续监听、内容传输不因此结束。不得额外以正文、工具记录或回传回执作为网页结束判断条件。
2. 首次绑定和重新连接时，补齐同一网页对话中尚未同步到 Paseo 的信息；不通过重新向 ChatGPT 发送原请求来补齐。
3. Paseo 的停止按钮与 ChatGPT 网页按钮状态保持一致。Paseo 点停止，网页也停止；网页停止后，Paseo 按同步规则自动停止。不得把没有网页停止按钮的情形擅自替换为拒绝授权或其它操作。
4. 图片、文件保留在 Paseo 中可预览、可下载的要求，不降级为只有网页链接。

真实授权测试已观察到：Allow once / Deny 授权框可见时，主按钮为 Start Voice，因此按上述按钮规则属于待命。需求不因这个场景另增特例。

## 验证与实现约束

仅改 CIP，不修改 Paseo 宿主。优先验证 Paseo 收到本轮结束后，后续授权、内容更新和历史补齐是否仍能正确承接；不得把方案或离线验证当作已实机交付。技术限制要如实报告，不擅改已确认业务规则。

不自动批准授权，不重复发送原任务。保留前期已确定的兼容范围及其它安全约束。
