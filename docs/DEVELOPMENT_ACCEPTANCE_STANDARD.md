# CoS in Paseo｜开发与验收规范（轻量版）

> 2026-10-15 · v1.1。适用于本项目后续开发、修复、升级和验收。产品范围见 [产品说明书](PRODUCT_MANUAL.md)。
>
> **原则：一项任务、一份简要记录、三步闭环。** 不再要求每项任务都填长工作包、经过 7 道审批或创建多份报告。**测试强度按风险决定**，但不得牺牲消息安全和真实验收。

## 一、做事只用三步

### 1. 想清楚

开始前用几句话确定：**改什么、改哪些文件、成功长什么样、哪些行为不能破坏**。先读现有代码、任务要求和最近失败证据，避免重复开发。

- 普通修复：直接记录在 Presure 任务或一份项目说明中即可。
- 跨模块/改协议/有数据迁移：再补简短设计，写出会话身份、消息状态和回滚方案。
- 有其他 Agent 在运行：先确定隔离方式；不能为了测试打断共享 Runtime 或刷新其 ChatGPT 页面。
- 每个模块都要能单独用测试输入验证，**但不需要独立服务或重复通信框架**。

### 2. 动手做

在现有模块内做最小改动，必要时保存旧文件；修问题的同时加一条**能复现旧问题**的测试和相应反向/异常测试。优先复用原 CoS 的公开网页采集逻辑，保持一套 Paseo Provider、一套共享 Runtime 和一个 Chrome 扩展。

以下规则无论任务大小都必须保留：

1. **一次发送：** 发送回执不明就保留待确认/失败记录，**不能自动重发**；网页自行发送的消息只镜像，不再代发。
2. **精确归属：** Conversation、Runtime session、turn、lease、tabId、documentKey、原生 user ID 均按适用环节验证，不根据标签标题或相似文本猜身份。
3. **仅公开内容：** 可以解析公开的 `collapse`；不能提取私有推理、隐藏分组、不可见工具输入/输出。
4. **不越权：** 不自动批准 ChatGPT 工具、不传递未经授权的 MCP 权限；外部工具副作用必须单独核对。
5. **保护其他会话：** 不强制重启共享 Runtime、清锁或强停其他 Agent。**Chrome 扩展更新的专用恢复流程**可刷新它明确管理的已绑定标签，并重新唤醒 Agent；不能连带刷新无关 ChatGPT 标签、隐瞒正在生成的轮次可能被页面刷新中断或声称工具副作用已完成。
6. **渲染不污染其他 Agent：** Chatmode 的富文本/工具卡调整只能影响 Chatmode；不能盲目接管 Paseo 全局消息组件。

### 3. 检查、交付

先跑受影响模块的自动化测试；涉及网页或生命周期的改动，再用**专用真实 ChatGPT + Paseo Agent** 验证。测试通过后再在安全窗口发布、回填 Presure；没有真实验收，就写“代码完成、待验收”，**不能标 Done**。

> **重要区分：** 源码正确 ≠ 离线浏览器通过 ≠ 真实网页登录页成功 ≠ 外部 MCP 实际执行成功。每一项只报告自己亲自验证到的层级。

## 二、按风险选择测试，不做无用仪式

| 改动类型 | 最低要求 | 是否需要真实账号 |
| --- | --- | --- |
| 只改文字/文档 | 检查内容、链接和前后描述一致 | **不需要** |
| 纯内部算法、格式、单元测试 | 相关测试 + Node 全量回归 | 通常不需要 |
| TypeScript、Provider、CoS 移植或 Chrome 扩展 | 上述测试 + 类型/SDK/来源检查（按涉及模块）+ 离线 MV3 浏览器测试 | 更改真实用户行为时需要 |
| 发送、Stop、身份绑定、唤醒、原生工具事件、部署迁移 | 自动化 + 对抗测试 + 真实三端联调 | **必须**；运行中其他 Agent 不允许被打断 |
| 纯 UI 改动 | 组件/类型检查 + 桌面和相关移动端视觉验收 + 不影响其他 Provider | 如影响真实消息显示，则需要 |

项目已有命令（使用已配置 Node 环境）：

```sh
npm run check
npm test
npm run verify:upstream   # 改 CoS 移植层时
npm run typecheck         # TypeScript/界面/Provider 有改动且已安装依赖时
npm run test:sdk          # Provider 事件有改动且 SDK 可用时
npm run test:mv3          # Chrome/通信层改动，需有隔离浏览器测试环境
```

没有依赖或浏览器环境时写 **BLOCKED**，不能改称 PASS。离线 Chrome 测试必须使用独立 profile 和临时 Runtime；不把生产 ChatGPT 账号/运行中的会话当夹具。

## 三、实际验收只抓关键场景

| 编号 | 关键场景 | 通过标准 |
| --- | --- | --- |
| **T1** | 安装、配对、配置 | 本机连接、模型/工具读回正确；不接受错 token 或错页 |
| **T2** | Paseo → ChatGPT | 首轮与第二轮成功、同一 Conversation、每条一次 Send，最终回 idle |
| **T3** | ChatGPT 网页 → Paseo | 原 Agent 收到用户消息、后续回复与终态；`origin=browser`，Paseo 不二次发送 |
| **T4** | Stop、关页、恢复 | **仅凭绑定 Conversation 重开原 URL**；消息按独立 ID 去重，结果未知不自动重发；不影响其他 Agent |
| **T5** | 公开思考与工具（COS2） | 真实网页至少 2 个不同 `callId`，Paseo 独立工具卡、名称/状态准确；有公开摘要时正确出现；无私有泄漏 |
| **T6** | 错误与并发 | 回执不明、断线、后台限速、双 Agent、换页/重复事件不会误报成功或串会话 |
| **T7** | UI/图片（改动时） | 消息排版、折叠、图片与回放正确；桌面/移动端可用，不影响其他 Provider |
| **T8** | Chrome / Paseo 自动唤醒 | Chrome 退出后 Paseo 应启动 Chrome；Paseo 退出但 Chrome 仍在线时，已配对扩展经受限本机入口唤起 Paseo；Chrome 扩展更新应刷新**原插件管理的**已打开对话并自动恢复 Agent 观察（不重发、不串页）。**代码候选尚未实机验收** |

**按任务选择验收，不是每次都跑满 T1–T8。**

- **COSINPASEO-1：** 重点 T2、T3、T4、T6、T8。一次性安装/配对不作为每轮用户操作要求；T8 需真机验证 Chrome 与 Paseo 分别退出再由另一侧唤起，不能只凭 `open` 返回成功计 PASS。
- **COSINPASEO-2：** 重点 T5、T6。若真实页面没出现公开摘要，记“本案例没有摘要证据”，不能把空结果算作摘要通过；应另找确实显示摘要的安全场景。
- **消息 UI：** 重点 T7，连带 T2/T5 的正常显示和其他 Provider 回归。
- **一般内部改动：** 只跑受影响功能和必要回归，不因改文档或纯内部函数强制登录 ChatGPT。

**实机证据必须同时对应：** ChatGPT 中的用户/工具活动、Chrome/Runtime 的同轮身份、Paseo 的实际时间线。工具只读文件的返回值正确，并不自动证明 `tool_call` 卡片已经同步。Stop 成功也不能证明已发起的外部 MCP 进程被杀掉。

## 四、状态、隐私和异常怎么记

只保留四个验收结论：

- **PASS**：本次真实执行且有证据，符合预期。
- **FAIL**：执行了，结果不符合；写清错误与复现步骤。
- **BLOCKED**：权限、登录态、工具环境或活跃生产 Agent 阻止安全验收；写清前置条件。
- **NOT RUN**：本轮未做。历史 PASS 只能引用为历史证据，不能当本轮 PASS。

任务仍使用 Presure 原有状态；实现写完但真实验收未完，保留 **In Progress**。未完成范围、权限边界或验收口径如果要删改，**先在任务中取得明确批准并留痕**，不允许为了标 Done 隐性放宽。

**统一交付记录（每项任务只需一份，放在 Presure 评论或项目 `docs/`）：**

```text
任务：
本次改动（文件/关键逻辑）：
测试（命令、通过数、真实或模拟）：
实机验收（PASS/FAIL/BLOCKED/NOT RUN + 证据）：
风险或未完成项：
是否已部署、当前版本/脚本证明与回滚位置：
结论：可 Done / 保持 In Progress
```

私有 token、配对码、完整私人会话、隐藏推理或未授权工具参数不能进入报告。日志需要时只保留脱敏 ID/片段、状态与数量。

## 五、上线只守四个关口

1. **确认安全窗口：** 相关共享 Runtime 没有活跃轮次、待授权和不确定发送。若仍在运行，**只做隔离测试，不部署**。不要手动清空状态来制造空闲。
2. **保留恢复能力：** 停止共享 Runtime 后备份其状态和旧代码/扩展，核对数据兼容；不能删活锁、拿不兼容旧状态直接回滚。
3. **更新并核对真实版本：** 按实际改动成套加载相关 Paseo 插件和 Chrome 扩展，刷新**明确空闲**的专用网页；核对 CIP 协议、engine、扩展实际加载脚本、Runtime epoch 或构建哈希。**数字版本相同不等于代码已经生效**。文档修改不要求升级插件版本。
4. **小范围实机验证后放行：** 用新测试消息验证收发、恢复及受影响的工具/UI。失败即停止扩大使用，按安全备份/兼容方案回滚；**不重发结果不明的旧消息**。把结果和未完成项写入同一交付记录。

不预设“完成状态必须在 10 秒内”一类未经基线证实的硬指标。先记录真实网页结束到 Paseo `completed` 的耗时与复现条件，确认用户体验目标后再决定阈值；**不能通过弱化终态验证制造更快数字**。

## 六、当前执行顺序

1. **先验 COSINPASEO-1：** 验升级后 `CONTENT_UNAVAILABLE` / `STOP_UNCONFIRMED` / `REOPEN_IDENTITY_UNPROVEN` 相关恢复场景，确保网页活动持续回传、原 Conversation 不变且仅一次发送。
2. **再验 COSINPASEO-2：** 真正触发至少两次公开工具调用，在 Paseo 检查各自 `tool_call`；有公开 recap 才校验 reasoning。沿网页读取 → 扩展 → Runtime → Provider 定位缺失环节。
3. **最后做 Chatmode UI：** 优化 Markdown、代码、表格、公式与折叠时间线，并单独验收桌面/移动端；不扩大到其他 Agent 的消息组件。

历史设计、具体 API 与前次测试日志需要时再查 [协议](PROTOCOL.md)、[旧实机报告](COSINPASEO-REAL_ACCEPTANCE_20261015.md) 和 [恢复修复记录](COSINPASEO-1_RELOAD_RECOVERY_20261015.md)；**日常开发只按这一份轻量规范执行**。
