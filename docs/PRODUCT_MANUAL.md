## 1. 这是一个什么产品

把**真实登录的 ChatGPT 网页**接入 Paseo，让用户从 Paseo 原 Agent 收发消息、切换已经授权的 `@` 应用，并查看 ChatGPT 对用户公开的回复、思考摘要和工具过程。

目标不是做第二个 ChatGPT，也不是另造 CoS 桌面程序；**Paseo 是工作入口，ChatGPT 网页是执行端**。

```text
Paseo Agent → Paseo 插件/共享 Runtime → 本机 Chrome 扩展 → ChatGPT 网页
           ← 可信消息、公开过程、完成状态 ←
ChatGPT 网页 → 用户已授权的 @ 应用 → 原有 MCP 服务
```

Chrome 扩展与 Paseo 后台须在**同一台主机**；Paseo 手机端可以连接这台后台。Runtime 默认只监听本机回环地址，不对公网提供通用代理或文件执行能力。

## 2. 用户怎样使用

1. 在 Paseo 安装本项目插件、在 Chrome 加载本项目 `extension/`，用 Paseo 设置页的一次性配对码连接。首次安装步骤见 [README](../README.md)。
2. 在 Chatmode 设置中选择模型、思考档位、已授权 `@` 应用；Paseo 输入区保留一个原生“工具”下拉，支持无工具、单应用及预设组合。
3. 创建 Agent 后发送消息：首次发送才打开正式 ChatGPT 标签；以后优先沿用同一对话。**已绑定 Agent 的唯一用户侧前提是保存了 ChatGPT Conversation。** 关闭标签后发送新消息，自动打开原对话；Chrome 未启动时由 Paseo 拉起，Paseo 退出但 Chrome 仍运行时由已授权扩展通过本机唤醒入口拉起。网页端直接发送的新消息回到原 Agent，**不能二次代发**。

默认并发 2 路，可调整为 1–8；超额请求排队，排队不等于消息已送达。

## 4. 必须守住的行为边界

- **只发一次：** 已由网页发送的消息只同步；发送回执未知时不自动重试，不猜测“已成功”。
- **身份准确：** 打开原会话只需绑定的 Conversation；旧原生消息 ID **不是重开前提**。新消息发送、工具事件和回执仍严格验证各自轮次、文档、lease、原生 ID，不靠标题或相似文字认领。
- **只读公开过程：** `collapse` 是可见内容折叠；可同步其中公开摘要/工具状态，但不提取 `analysis/private/hide_all`、内部推理或未显示的工具参数。
- **权限不越界：** 不替用户批准工具、不直接继承 Paseo 的 MCP 权限。ChatGPT Stop 也不证明外部 MCP 任务已经停止。
- **更新恢复：** Chrome 扩展版本更新会自动刷新**属于该插件、已绑定的打开中对话标签**，加载新版采集脚本，再请求唤醒原 Paseo Agent 并恢复观察；不刷新无关 ChatGPT 标签或重发未知状态消息。**刷新可能打断当时网页中的生成/工具等待，不能保证外部任务继续或完成**；状态不确定时保留警告。非此更新流程不强停其他 Agent、不清锁、不擅自重启共享 Runtime。
- **数据保护：** 状态目录 `~/.cos-in-paseo/` 含会话记录，权限受限但**未加密**；不得外传 token、完整私人会话或私有推理。
