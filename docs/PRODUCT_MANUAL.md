# Chatmode in Paseo｜产品说明书

更新：2026-10-19；本说明针对 **Paseo 插件 0.1.0-alpha.4.51、Chrome 扩展 0.2.53、CIP v9**。版本以 `package.json`、`extension/manifest.json` 和 `server/protocol.mjs` 为准。它仍属于 alpha，不是正式验收声明。

## 1. 产品定位

在 Paseo 创建 Chatmode Agent，通过本项目 Chrome 扩展操作登录状态下的 ChatGPT 网页，读回真实可见的回答、过程、工具卡和生成媒体。**Paseo 是工作入口，ChatGPT 网页负责执行；本项目不是一个独立推理模型，也不会把 Paseo 内置 MCP 自动导入网页。**

```text
Paseo Agent ↔ 本项目 Provider / 共享 Runtime ↔ Chrome 扩展 ↔ ChatGPT 网页
                                                        ↓ 已授权 @ 应用
                                                  外部 MCP/工具服务
```

Chrome 与 Paseo 后台需在同一电脑；手机上的 Paseo 可以连接该后台。桥接服务只监听本机回环地址。

## 2. 使用步骤

1. 运行 `npm ci` 与必要测试后，从源码目录安装 Paseo 插件；在 Chrome 加载同目录下的 `extension/`，确认两端兼容的 CIP 版本。
2. 在 **Paseo Settings → Plugins → Chatmode 配置** 生成一次性配对码；在 Chrome 扩展弹窗填入本机地址和配对码。目录读取依赖已登录网页和已授权的应用。
3. 保存模型、思考强度、`@` 应用默认组合；创建 Chatmode Agent，首条消息才打开专用 ChatGPT 标签。后续沿用同一绑定 Conversation。
4. 在 Paseo 查看网页状态与公开来源；网页直接输入的新消息通过同一观察链路回传，不再代发一次。Stop 只操作当前网页 Stop，不代表外部 MCP 工作必然结束。

同时进行的网页轮次数可设置为 1–8（默认 2）。排队表示尚未送达。带图片或文件的输入最多 4 件，单件 12 MiB、合计 24 MiB；先在原生输入框上传并确认，再写正文和发送。

## 3. 新版核心设计

| 功能 | v9 当前行为 |
| --- | --- |
| 一次性发送与回执 | 精确 command/lease/页面身份；结果未知绝不自动重新点击 Send |
| 已知未发送清理 | 删除未发送的网页草稿和可确认的本地临时副本，留下 ID 防重放；无服务端证明时保留证据 |
| 持续观察 | 独立读取网页可见 Stop/Send/Voice 控件、公开文本、图片、工具和授权卡 |
| 源内容存储 | 按来源 ID、修订与顺序持久保存；读取失败不构成另一种状态证据 |
| Paseo 内容交付 | 独立的投影与交付过程；本地落盘不代表宿主已经消费，也不保证原生机器最终答复字段有值 |
| 网页权限 | 默认人工在 Paseo 或 ChatGPT 处理。可选择开启自动允许，但当前策略包括持久授权，风险见下文 |
| 归档与恢复 | 归档记录可移入 archive；已绑定对话支持重新打开、恢复观察，不重发旧消息 |
| 媒体 | 支持公开图片预览和受归属保护的文件传输；真实文件可用性要按具体场景验收 |

## 4. 授权、安全和已知限制

- **自动允许网页授权默认关闭。** 开启时会优先选择识别出的持久允许按钮，也可能尝试同层多个允许按钮。这可能扩大 ChatGPT 账号长期权限；Paseo 目前无法撤销已生效的网页持久授权。关闭开关会撤销尚未认领的自动命令；用户在 Paseo 手动拒绝会抢占尚未认领的自动允许。已认领的命令有点击前服务端二次校验；已发生的网页点击无法撤销。若按钮内容变化或点击结果不明，系统终止后续自动操作且不重复点击。
- 不自动绕过 ChatGPT 限额、替用户登录、不泄露浏览器 token，不执行未经授权的本机命令。项目不通过任意文件/Shell 代理访问开发机。
- 网页授权卡内容更新会生成新请求 ID 并使旧 ID 失效。网页关闭或授权结果未知时，原生 Paseo 权限接口不支持不附带 Deny 的自动移除；旧卡会明确提示无效或待核对。用户可明确按旧卡「拒绝」仅清理本地提示，**不会再向网页发出 Deny**，且不代表此前网页真的拒绝。
- 本地状态 `~/.chatmode-in-paseo/` 未加密，含会话历史与配对信息；只能在可信电脑保存。
- ChatGPT 页面 React 结构可能变化；暂时读不到消息或来源时应明确显示异常，不能宣称已完成或已失败。
- 宿主对前后轮次交错的部分回传，可能在时间线中归到较新的轮次；Paseo 原生最终答复字段也可能无法直接读取插件内容。参见 [宿主交付限制](HOST_CONCURRENT_DELIVERY_GATE.md)。
- 原版宿主把某轮次正式标记失败之后，同连接直接重新激活该轮仍有门禁（OBS-P1）；普通的暂时观察失败不应立即变成该终态。参见 [专项核查](OBS_P1_VERIFICATION.md)。

## 5. 完成标准与升级

`npm test`、`npm run typecheck`、`npm run test:sdk` 和隔离 Chrome/MV3 回归只能证明各自执行过的路径。**真实已登录账号 + Chrome + Paseo 宿主的收发、工具权限、Stop、媒体、断线、归档和恢复仍需要独立验收**；版本号更新或 CI 全绿不是替代。

升级运行中的插件之前，须等待安全窗口，备份退出后的 `CIP_STATE_DIR`，成套替换 Paseo 与 Chrome，核对 Runtime `/hello` 的 protocol、扩展实际加载版本与原 Agent 观察身份。不要清理活锁或强制重放结果未知的消息。详细步骤和测试命令见 [README](../README.md)、[测试与验收指南](TESTING.md) 与 [CIP v9 协议](PROTOCOL.md)。
