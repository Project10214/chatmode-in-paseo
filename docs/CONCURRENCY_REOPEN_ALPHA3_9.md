# alpha.3.9 — 并发设置、等待名额与关闭标签页后的续聊

## 已实现

Paseo 的 Chatmode 配置页新增“并发标签页”：1–8 路，默认沿用 2，建议首次设为 4。该值保存到现有 state.json 的 runtimeSettings.maxConcurrent，通过已认证的 Paseo RPC 修改；保存后立即生效，重启保留。这里限制桥接正在执行/准备的轮数，不限制闲置网页总数，也不代表 ChatGPT 账号必然允许相同并发。

超额的新请求先在共享 Runtime 内等待名额，所有 Provider 连接共用一个先进先出的队列。显示队列位置，可用 Paseo 停止按钮取消。取得名额后才准备标签页；准备到真正发送之间始终持有名额，避免同时开空白网页后才拒绝。减少上限不停止已经开始的任务，只限制后续启动。

等待队列只活在当前 Runtime：关闭 Agent、Provider 或重载插件会取消尚未发送的等待请求，不跨重启自动补发。已进入发送且结果不明的消息仍保持原有不重发保护。名额最长等待采用现有整轮时限 3 小时，超时明确失败。

## 关闭标签页续聊

本次现场日志中的 send 未被浏览器领取，旧 tabId 仍留在 Runtime，最终等满 BRIDGE_TIMEOUT。新增发送前 ensure 命令：

1. 会话必须处于 idle；从持久会话/最近已确认回执取得原 conversationId 和最后用户原生消息 ID。
2. 原标签页仍存在时检查其当前对话与原生消息；不抢占手工切换后的网页。
3. 原标签页已关闭时，只打开已绑定的 https://chatgpt.com/c/<conversationId>。加载后核对原对话和最后消息，重新核验配置。
4. Runtime 原子提交新 tabId/documentKey 后才允许当前新消息进入 Send。不会重新发送旧请求。
5. 网页/登录不可用、会话被删除、身份不符等准备失败直接反馈，不再无提示等满 90 秒。无法确定已领取状态时保留原来保守处理。

新增 /fail-unclaimed 接口沿用本地接口的认证和来源校验，只能终结尚未领取、没有 lease 的命令；不能覆盖已授权/已发送的结果。ensure 的领取和结果两次核对原生消息。不同会话不能抢占彼此标签页。

适用范围：关闭已完成/已明确未发送的空闲会话标签页后，发送一条新消息。生成途中关页而导致 BROWSER_BINDING_LOST、RECEIPT_UNCONFIRMED 等 blocked 状态，不会擅自解除阻断或自动续发旧任务。整个 Chrome 退出后，需 Chrome 与扩展重新上线；此功能不是启动 Chrome 主程序。

真实 MV3 测试装载未打包扩展，使用 Chrome 标签页、MAIN/ISOLATED 脚本、本地 HTTP Runtime、已安装 Paseo 0.11.2 SDK 校验事件。网页和回答由隔离本地 TLS 夹具提供。已验证：关闭标签后重开同一会话、四路并发、两路上限下排队不提前开页、取消等待、2→4→1 热修改不打断任务、手工切换到别的对话及时拒绝。

旧 provider 单元夹具及 browser-provider-flow 驱动新增 ensure 应答/身份字段，保留原来的重复发送、单次结果和隔离断言。

## 升级

两端一起重载：Paseo 插件 alpha.3.9，Chrome 清单 0.1.11、显示 alpha.3.9。刷新空闲 ChatGPT 页面，无需重新配对。不要在尚有工作时重载；重载会取消等待与现有运行跟踪。进入并发区域设 4 并点击“应用并发上限”。完成一轮后关闭对应网页，再在同一个 Paseo 对话发新消息，检查自动重开原链接并收到回答。

本次没有修改生产状态/已有配对，没有重发旧消息、清空历史或强制重载正在运行的插件。源码备份在 .work/concurrency-reopen-alpha3-9/before/。未上传 GitHub。

官方契约核对：https://paseo.sh/docs/plugins/providers （send 接收工作，结果由 onEvent 发布；每条 clientMessageId 一个 prompt_result；会话通过持久身份恢复）。
